# Line Bot 對話/功能設計

## 主題

**DeFi 知識助手** - 一個專門回答去中心化金融（Decentralized Finance, DeFi）相關問題的智慧聊天機器人。

本 Bot 專注於提供 DeFi 相關知識，包括：
- DeFi 基礎概念與原理
- 去中心化交易所（DEX）
- 流動性挖礦與流動性池
- 借貸協議
- 風險管理
- 智能合約

## 功能列表

### 1. 對話功能
- **文字對話**：使用者可直接輸入 DeFi 相關問題，Bot 會使用 RAG（Retrieval-Augmented Generation）技術從知識庫檢索相關資訊並生成回答
- **圖形化選單**：提供按鈕式選單，讓使用者透過點擊瀏覽不同類別的問題
- **對話脈絡維持**：Bot 會記住對話歷史（最多 5 輪），讓回應更連貫

### 2. 導航功能
- **主選單**：顯示所有知識類別（6 個類別）
- **類別瀏覽**：點擊類別後顯示該類別下的所有問題
- **問題查看**：點擊問題後顯示完整答案
- **返回功能**：隨時可以返回上一層或主選單

### 3. 指令功能
- `help` / `幫助`：顯示使用說明
- `stats` / `統計`：查看個人統計資訊（訊息數、對話數、最後活躍時間）
- `info` / `資訊`：查看 Bot 資訊
- `menu` / `主選單`：顯示主選單（類別按鈕）

### 4. 管理功能
- **對話紀錄儲存**：所有對話都會持久化儲存到 MongoDB
- **統計資訊**：追蹤使用者訊息數、對話數、活躍時間
- **即時更新**：管理後台可即時看到新訊息和新會話

### 6. 文字對話（使用者輸入文字問題）

**流程：**
1. 如果訊息長度 < 10 字元：直接使用 LLM 回答（快速回應）
2. 如果訊息長度 ≥ 10 字元：使用 RAG 系統
   - 從知識庫檢索相關內容（向量相似度搜尋）
   - 將知識庫內容和對話歷史一起送給 LLM
   - LLM 基於知識庫內容生成回答
3. 如果 RAG 失敗：降級到直接 LLM 回答
4. 如果 LLM 失敗：使用預設降級回應

**回應格式：**
- 簡潔清晰（200 字以內）
- 繁體中文
- 基於知識庫內容，不編造資訊
- 如果知識庫沒有相關資訊，誠實告知並建議相關問題

## 對話脈絡：在回覆時維持上下文

### 對話歷史管理

1. **對話歷史限制**：最多保留最近 5 輪對話（使用者訊息 + Bot 回應）
2. **對話歷史格式**：
   ```
   使用者：[使用者訊息]
   Bot：[Bot 回應]
   ```
3. **對話歷史使用**：
   - 在 RAG 回應中，對話歷史會與知識庫內容一起送給 LLM
   - LLM 可以根據對話歷史理解上下文，提供更連貫的回答
   - 例如：使用者問「什麼是 DeFi？」，接著問「它有什麼優勢？」，Bot 能理解「它」指的是 DeFi

### 對話狀態管理

1. **當前節點追蹤**：每個對話都有一個 `currentNodeId`，記錄使用者目前在對話圖中的位置
2. **節點類型**：
   - `root`：主選單
   - `category`：類別節點
   - `question`：問題節點
   - `answer`：答案節點
3. **狀態恢復**：當使用者點擊按鈕時，系統會根據 `currentNodeId` 導航到對應節點

### 文字指令導航

使用者可以透過文字指令進行導航：
- `主選單` / `menu`：返回主選單
- `返回` / `back`：返回上一層（如果可能）

## 回應設計：根據預設腳本 and/or LLM 回覆，包裝成適當的回應

### 1. 按鈕導航回應

**流程：**
1. 使用者點擊按鈕 → LINE 發送 postback 事件
2. 系統根據 postback.data（節點 ID）導航到對應節點
3. 根據節點類型渲染對應的 LINE 訊息：
   - `root` / `category`：按鈕模板或輪播模板
   - `question`：按鈕模板（顯示問題 + 查看答案按鈕）
   - `answer`：文字訊息（答案）+ 按鈕模板（導航按鈕）

### 2. 文字對話回應

**流程：**
1. 檢查是否為指令 → 如果是，執行指令邏輯
2. 如果不是指令：
   - 短訊息（< 10 字元）：直接 LLM 回應
   - 長訊息（≥ 10 字元）：RAG 回應
3. 將回應包裝成 LINE 文字訊息格式
4. 發送給使用者

### 3. 錯誤處理與降級

**錯誤類型：**
1. **LLM 配額錯誤（QUOTA_EXCEEDED）**：
   - 回應：`抱歉，AI 服務暫時無法使用，請稍後再試或聯繫管理員。`
2. **LLM 認證錯誤（AUTH_ERROR）**：
   - 回應：`抱歉，AI 服務暫時無法使用，請稍後再試或聯繫管理員。`
3. **可重試錯誤（retryable）**：
   - 使用預設降級回應：`抱歉，我目前無法回答這個問題。請嘗試詢問其他 DeFi 相關的問題，或輸入 "help" 查看使用說明。`
4. **RAG 失敗**：
   - 降級到直接 LLM 回應
   - 如果 LLM 也失敗，使用降級回應
5. **資料庫錯誤**：
   - 記錄錯誤日誌
   - 嘗試發送錯誤訊息給使用者（如果可能）

### 4. 回應格式規範

**文字訊息：**
- 最大長度：2000 字元（LINE 限制）
- 語言：繁體中文
- 格式：簡潔、清晰、分段（如果內容較長）

**按鈕模板：**
- 最多 4 個按鈕（LINE 限制）
- 按鈕標籤：最多 20 字元
- 按鈕 data：最多 300 字元

**輪播模板：**
- 最多 10 個項目（LINE 限制）
- 每個項目標題：最多 40 字元
- 每個項目文字：最多 120 字元

### 節點類型說明

1. **root（根節點）**：
   - 主選單，顯示所有類別
   - 子節點：6 個類別節點

2. **category（類別節點）**：
   - 顯示該類別下的所有問題
   - 子節點：該類別的所有問題節點

3. **question（問題節點）**：
   - 顯示問題內容
   - 子節點：對應的答案節點

4. **answer（答案節點）**：
   - 顯示完整答案（經過 LLM 優化）
   - 無子節點（葉節點）

### 導航機制

1. **按鈕點擊**：透過 postback 事件，data 欄位包含節點 ID
2. **文字指令**：支援「主選單」、「返回」、「back」等指令
3. **狀態追蹤**：每個對話記錄當前節點 ID，方便狀態恢復

## 知識庫設計

### 知識庫結構

- **總問題數**：40+ 個 Q&A 對
- **類別**：6 個主要類別
  - DeFi 基礎（10+ 個問題）
  - 去中心化交易所（DEX）（8+ 個問題）
  - 流動性挖礦（8+ 個問題）
  - 借貸協議（8+ 個問題）
  - 風險管理（6+ 個問題）
  - 智能合約（6+ 個問題）

### 知識庫格式

每個知識庫項目包含：
- `question`：問題文字
- `answer`：答案文字
- `category`：類別（enum）
- `metadata`：
  - `tags`：標籤陣列
  - `difficulty`：難度（beginner / intermediate / advanced）
- `embedding`：向量嵌入（1536 維度，用於相似度搜尋）

### RAG 檢索機制

1. **向量化**：使用 OpenAI `text-embedding-3-small` 模型將問題轉換為向量
2. **相似度搜尋**：使用餘弦相似度在知識庫中搜尋最相關的項目
3. **Top-K 檢索**：預設檢索前 3 個最相關的項目（可調整）
4. **相似度閾值**：預設 0.7（可調整）

## 技術實現細節

### 1. LINE Messaging API 整合

- **Webhook 端點**：`/api/webhook`
- **支援事件類型**：
  - `message`：文字訊息
  - `postback`：按鈕點擊
  - `follow`：使用者加入
  - `unfollow`：使用者封鎖

### 2. 資料庫設計

**User 模型：**
- `lineUserId`：LINE 使用者 ID
- `displayName`：顯示名稱
- `messageCount`：訊息數
- `lastActiveAt`：最後活躍時間

**Conversation 模型：**
- `userId`：使用者 ID
- `active`：是否為活躍對話
- `currentNodeId`：當前節點 ID
- `startedAt`：開始時間
- `endedAt`：結束時間

**Message 模型：**
- `conversationId`：對話 ID
- `role`：角色（user / assistant）
- `content`：訊息內容
- `messageType`：訊息類型（text / postback）
- `timestamp`：時間戳

**KnowledgeBase 模型：**
- `question`：問題
- `answer`：答案
- `category`：類別
- `embedding`：向量嵌入
- `metadata`：中繼資料

### 3. 錯誤處理與降級

**LLM 錯誤處理：**
- 自動重試（最多 3 次）
- 重試延遲（1 秒）
- 錯誤分類（可重試 / 不可重試）
- 配額錯誤特殊處理

**降級策略：**
1. RAG 失敗 → 直接 LLM
2. LLM 失敗 → 預設降級回應
3. 資料庫錯誤 → 記錄日誌，嘗試發送錯誤訊息

### 4. 效能優化

- **短訊息優化**：< 10 字元的訊息跳過 RAG，直接使用 LLM（更快）
- **快取機制**：類別問題列表快取 5 分鐘
- **並行處理**：向量搜尋和 LLM 呼叫可並行處理
- **超時控制**：LLM 呼叫超時 20 秒

## 總結

本 Bot 設計結合了：
1. **結構化導航**：透過對話圖提供清晰的選單導航
2. **智慧對話**：使用 RAG 技術提供準確、基於知識庫的回答
3. **上下文維持**：保留對話歷史，讓回應更連貫
4. **錯誤處理**：完善的錯誤處理和降級機制
5. **使用者體驗**：多種回應格式（文字、按鈕、輪播）提供良好的互動體驗
